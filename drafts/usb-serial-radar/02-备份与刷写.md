# A. 整片备份与刷写（PVE Docker esptool）

## 为什么用 PVE + Docker
- CH343 现在在 **PVE 宿主** `/dev/ttyACM0`，尚未直通。
- Docker 一次性容器，**不在 PVE 上长期 pip 装包**。
- 刷稳后再直通给 HA，避免刷写期 HA serial 抢口/复位环。

## 刷写前检查清单
```bash
# 在 PVE root@10.10.10.10
lsusb -d 1a86:55d3
ls -l /dev/ttyACM0 /dev/serial/by-id/ 2>/dev/null
fuser /dev/ttyACM0 || true   # 确认无进程占用
# 底板外置 5V 已拔（禁止 USB + 底板双供电）
```

## 备份目录（建议）
```text
PVE:  /root/backups/esp32-ld2410-7ce8b1a2dbb0/
3038: backups/esp32-ld2410-7ce8b1a2dbb0/   # 可拷回仓库；*.bin 勿 git commit，只留 sha256 说明
```

## 完整备份（16MB Flash）
芯片 **ESP32-S3-N16R8** → Flash **16MB = 0x1000000**。

```bash
STAMP=$(date +%Y%m%d-%H%M%S)
DIR=/root/backups/esp32-ld2410-7ce8b1a2dbb0
mkdir -p "$DIR"

docker run --rm --device=/dev/ttyACM0 \
  -v "$DIR":/backup python:3.12-slim \
  bash -lc "pip -q install esptool==4.8.1 && \
    esptool.py --chip esp32s3 -p /dev/ttyACM0 -b 460800 \
      read_flash 0x0 0x1000000 /backup/fullflash-${STAMP}.bin && \
    ls -la /backup/fullflash-${STAMP}.bin && \
    sha256sum /backup/fullflash-${STAMP}.bin | tee /backup/fullflash-${STAMP}.sha256"
```

记录：路径、sha256、时间。备份失败 **禁止** 继续刷新固件。

### 进下载模式
1. **优先**：CH343 自动 DTR/RTS（esptool 默认会拉）。
2. **失败时**：按住 **BOOT** → 点 **RST** → 松开 BOOT，再跑命令。
3. 原生 USB（`303a:1001`）不稳定，**备份/刷写只用 CH343**。

## 回滚（整片备份 @0x0 写回，保持不变）
```bash
# 将 BIN 换成实际文件名
BIN=fullflash-YYYYMMDD-HHMMSS.bin
DIR=/root/backups/esp32-ld2410-7ce8b1a2dbb0

docker run --rm --device=/dev/ttyACM0 \
  -v "$DIR":/backup python:3.12-slim \
  bash -lc "pip -q install esptool==4.8.1 && \
    esptool.py --chip esp32s3 -p /dev/ttyACM0 -b 460800 \
      write_flash --flash_mode keep --flash_freq keep --flash_size keep \
      0x0 /backup/${BIN}"
```

## 刷入新固件（选定方案：四件套按固定偏移写入）

### 分区与偏移依据
`firmware/platformio.ini`：
- `board = esp32-s3-devkitc-1`（板定义默认 N8，但物理芯片为 **N16R8**）
- `board_build.flash_size = 16MB` / `board_upload.flash_size = 16MB`
- `board_build.flash_mode = dio`，`board_build.arduino.memory_type = dio_opi`（N16R8 为 8MB OPI PSRAM），`board_build.f_flash = 80000000L`（80m）
- `board_build.partitions = default_16MB.csv`（已在 box 上 `pio run` 验证）

刷写偏移写死（default_8MB/16MB 的 boot/app 偏移相同；**已编译核对**）：

| 文件 | 偏移 | 来源路径（Mac 编译后） |
|---|---|---|
| `bootloader.bin` | **0x0** | `drafts/usb-serial-radar/firmware/.pio/build/esp32-s3/bootloader.bin` |
| `partitions.bin` | **0x8000** | `drafts/usb-serial-radar/firmware/.pio/build/esp32-s3/partitions.bin` |
| `boot_app0.bin` | **0xe000** | `~/.platformio/packages/framework-arduinoespressif32/tools/partitions/boot_app0.bin`（不在 `.pio/build`，属 framework） |
| `firmware.bin` | **0x10000** | `drafts/usb-serial-radar/firmware/.pio/build/esp32-s3/firmware.bin`（**仅应用镜像，不可单独 @0x0**） |

Flash 参数与 ini 对齐：`--chip esp32s3 --flash_mode dio --flash_freq 80m --flash_size 16MB`。

> 若以后改自定义 `partitions.csv`，必须重算偏移，不得沿用上表。

### Mac 编译并收集四件套到 PVE 目录
```bash
# Mac
cd ~/Projects/yulaiwo/3038-网关-ha/drafts/usb-serial-radar/firmware
pio run
BUILD=.pio/build/esp32-s3
BOOT_APP0=~/.platformio/packages/framework-arduinoespressif32/tools/partitions/boot_app0.bin
ls -la "$BUILD/bootloader.bin" "$BUILD/partitions.bin" "$BUILD/firmware.bin" "$BOOT_APP0"

# 拷到 PVE（示例 scp）
scp "$BUILD/bootloader.bin" "$BUILD/partitions.bin" "$BUILD/firmware.bin" "$BOOT_APP0" \
  root@10.10.10.10:/root/backups/esp32-ld2410-7ce8b1a2dbb0/pio-upload/
```

### PVE 上写入（正确命令）
```bash
DIR=/root/backups/esp32-ld2410-7ce8b1a2dbb0/pio-upload

docker run --rm --device=/dev/ttyACM0 \
  -v "$DIR":/img python:3.12-slim \
  bash -lc 'pip -q install esptool==4.8.1 && \
    esptool.py --chip esp32s3 -p /dev/ttyACM0 -b 460800 \
      write_flash --flash_mode dio --flash_freq 80m --flash_size 16MB \
      0x0     /img/bootloader.bin \
      0x8000  /img/partitions.bin \
      0xe000  /img/boot_app0.bin \
      0x10000 /img/firmware.bin'
```

### 编译核对（box，2026-11-10，仅 pio run，未上传）
- `pio run`：**SUCCESS**（espressif32@6.9.0 / Arduino 2.x）
- 产物：
  - `.../.pio/build/esp32-s3/bootloader.bin` ≈ 15104 B → **0x0**
  - `.../.pio/build/esp32-s3/partitions.bin` ≈ 3072 B → **0x8000**（表内 app0@0x10000, otadata@0xe000）
  - `~/.platformio/packages/framework-arduinoespressif32/tools/partitions/boot_app0.bin` = 8192 B → **0xe000**
  - `.../.pio/build/esp32-s3/firmware.bin` ≈ 665840 B → **0x10000**
- box 编译树：`/workspace/usb-serial-radar-firmware/`

**禁止**：`write_flash … 0x0 firmware.bin`（应用镜像当整片会砖/起不来）。

### 未采用：merge_bin 合并后再 @0x0
本方案**选定四件套分偏移写入**（上表），不用 `merge_bin`，以免与「写死偏移」审核口径两套并存。若日后改用合并镜像，须另开草稿审：先 `esptool.py merge_bin -o merged.bin --flash_mode dio --flash_freq 80m --flash_size 16MB 0x0 bootloader.bin 0x8000 partitions.bin 0xe000 boot_app0.bin 0x10000 firmware.bin`，再 `write_flash 0x0 merged.bin`。

## 刷写参数铁规（2026-11-10 刷写失败后补）
- 新固件一律 `--flash_mode dio`，禁止 qio：该板 flash 只能按 DIO 启动，qio 会把 bootloader 头改成 QIO，导致 `ets_loader.c 78` 看门狗循环。
- 回滚整片镜像一律 `--flash_mode keep --flash_freq keep --flash_size keep`，保持原 ESPHome bootloader 头不被改写。
- PVE 上没有 Docker，实际执行用 `/root/venvs/esptool/bin/esptool.py`，参数与上面命令相同。
